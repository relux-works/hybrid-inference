# vLLM node adapter contract

This supervised stopgap uses the existing prefill-node HTTP and native delta formats. It is not a vLLM KV connector. Only the pinned vLLM 0.32.0 runner, one synchronous CUDA worker, dense 64-layer Qwen35 geometry, BF16 attention caches, BF16 convolution and f32 GDN state are launched. The existing exporter also understands its explicitly checked FP8 cache layouts. Unknown source hashes, architectures, geometry, parallelism, speculative/MTP configuration, speculative cache slots and unsupported checkpoint slots refuse. No inference or numerical qualification is implied by the CPU fixtures.

## Identity and authentication

`GET /v1/health` is public and returns the model identity, layout/fingerprint, context and request limits. Public bindings hide session counters unless authenticated. A backend health failure returns HTTP 503. All session routes, the link probe and metrics require a bearer token from the private id-to-token JSON. Tokens must be distinct, 16-256 characters. Foreign session IDs return 404 for reads, extends, snapshots and releases. The adapter binds to loopback by default; vLLM always binds to loopback.

`node-info.json` has the existing launcher's fields. `model_sha256` identifies the FP8 source: hash every local safetensors shard, config and index, then SHA256 the canonical sorted JSON name-to-hash mapping. The mapping is saved in `source-files.json`. The BF16 GGUF supplies the layout anchor and vocabulary fingerprint, and its separate hash is recorded. It does not identify the node's weights. The Q4 client must use the existing `--hetero-quant` admission and matching layout fingerprint. Source checkpoint/tokenizer provenance still needs operator confirmation; a layout match alone is insufficient evidence of equivalent weights or tokenizer semantics.

## Sessions and extends

`POST /v1/sessions` takes `model_sha256` and returns a random 32-hex `session_id`. `GET /v1/sessions` lists only the caller's sessions. `GET /v1/sessions/ID` returns `n`, `prefix_hash`, `tier`, `last_used`, `model_sha256`. `DELETE` returns 204 and removes the journal. Sessions are RAM-only; vLLM owns and evicts the shared prefix cache independently. Completed backend requests release their live blocks into that cache. Deleting a session removes its authority/journal; it does not flush other sessions' shared cached blocks. Up to 128 journals are admitted, with a context and 1 MiB HTTP request bound. The reported `ram_bytes` counts journals, not vLLM/device allocations or response staging. No native snapshot LRU is claimed.

`POST /v1/sessions/ID/extend` takes the unchanged `n0`, `prefix_hash_n0`, `tokens`, `return_delta` fields. A stale count/hash returns 409 with the actual `n` and `prefix_hash`. Malformed fields, invalid tokens, unsupported execution fields, unexportable ranges and conversion errors return HTTP 400 with `error`; backend transport loss returns 503. A failed request leaves the authoritative session journal unchanged. vLLM may retain harmless computed cache blocks after a failed conversion; a retry is a new capture and never trusts a partial manifest.

Only one mutation uses the backend at a time; competing session requests return 429 with `Retry-After`, preserving HTTP workers for health/admission. A failed/interrupted vLLM request or incomplete completion record marks the backend unhealthy and refuses subsequent requests until restart, so a still-running old forward cannot read a newer request's control file.

For `return_delta=false`, vLLM evaluates the complete accepted journal, the adapter returns 202 with its count/hash, and callers still verify progress through GET. This includes an unaligned tail. For `return_delta=true`, the adapter chooses `floor(requested_end / block_size) * block_size`. It evaluates only through that endpoint and exports `[n0, endpoint)` plus recurrent state at the endpoint. The full prompt is resubmitted to vLLM so its prefix cache can reuse aligned blocks; attention pages are gathered only for the new range. If `n0` is inside a block, only the leading attention rows are discarded; no historical recurrent state is fabricated. Prefix hits, eviction and actual recomputation remain vLLM's responsibility. The fake backend's reuse counters prove no live performance claim.

The hook captures only the final scheduled forward of this request, before postprocessing can sample/retire it. It skips intermediate chunks and never reuses the offline bridge's per-run capture cursor. Each request has fresh private control/output directories. The largest eligible endpoint has to be strictly greater than `n0` and fit the existing 512 MiB native body limit; otherwise the request refuses. Large transfers use multiple extends. No model/token downloads are performed.

`GET .../snapshot` recaptures an aligned current endpoint with the existing native slot-file magic/version/token journal. An unaligned historical endpoint returns 400 `{"error":"unaligned historical endpoint"}`. Historical endpoint overrides, speculative/MTP/slot fields and other unsupported extend fields refuse. Oversize snapshots refuse; they never truncate into a different state.

## Minimal compatible alignment extension

The original proxy and checker require an exact requested endpoint, so an adapter alone cannot transparently return a shorter delta. This change adds one optional capability: `export_block_size` in health/node info and proxy config. Its absence means 1 and preserves existing behavior. The client launcher copies the live capability into its existing config; no new user flags or benchmark modes are needed.

The proxy requests aligned chunk ends, imports the exact resulting deltas, and evaluates the remaining prompt tail locally. The native HYBD header still carries the actual `n1`, exact range tokens and prefix hash. Direct adapter callers also receive `X-Hybrid-Export-N1` and `X-Hybrid-Requested-N1`. A fresh unaligned request advances only to the exported endpoint; the unaccepted short suffix must be included in a later extend or evaluated locally. A no-progress aligned range refuses rather than emitting an empty delta.

The benchmark aligns only export endpoints and retains the complete prompt. The checker fixture's optional `local_tail_start` defaults to the old held-token boundary; when present, the imported chain must end at that exact count and the checker evaluates every remaining token on imported/same-partition/repeat contexts. A bounded alignment-only local tail is visible in the trace. A missed full block, HTTP/transport refusal or contract fallback still fails forced-offload verification. Heterogeneous results retain KL and use `weight_comparison=heterogeneous`; uncalibrated equivalence is not an exactness pass.

HYBD version 1, `llama-native-seq-v1`, q8_0 K/V, f32 recurrent state, section sizes, canonical XXH3-128 and SHA256 remain unchanged. Remote main was inspected at `528724c96` during this run and uses that envelope. Other in-flight native formats are not silently accepted.

## Process ownership

`deploy-vllm-node.sh start --state NEW_DIR --token-file PRIVATE_JSON` starts a supervisor, vLLM from the specified venv and the adapter. PID, process-group, start-tick, command and numbered log records live in the state directory. Startup probes the actual manager block size through the hook. `stop` signals the recorded supervisor only if its start ticks still match. The supervisor stops its two dedicated process groups, including surviving workers, and restores the original runner only if its installed bytes still match. An external runner modification is preserved with an explicit cleanup error and backup.

Normal stop, startup failure and INT/TERM/HUP use the same cleanup. SIGKILL/host failure cannot run cleanup: inspect the recorded PIDs/start ticks and `gpu_model_runner.py.original` before recovery. The script never stops another deployment or deletes the operator's venv. Node state/control files contain token IDs and must remain private.
