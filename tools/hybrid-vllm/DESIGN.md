# vLLM 0.32.0 prefill state bridge

Status: CPU prototype, GPU qualification pending. Base: `a3752b04cbd905bf61ffe6d9a4e7df738f26f4c2`. Scope: the approved private fork, no upstream submission. Source inspected: vLLM tag `v0.32.0`, commit `5df63a7203cdb9328d824a27b682e77c7b9928be`. No models or GPU were used on agents1.

## Route comparison

| Route | Source finding | Decision |
|---|---|---|
| A: V1 KV connector | `SupportsHMA.request_finished_all_groups` receives block IDs for all cache groups before release. NIXL implements HMA and explicit conv/SSM descriptors for Mamba/GDN, including TP mapping. Thus it can carry hybrid state; an attention-only connector cannot be assumed to. | Viable longer-term. NIXL adds device transfer registration, peer descriptors and completion ownership. It does not emit llama-native state, q8_0 or our envelope. |
| B: post-forward runner hook | The runner retains request token counts and group block tables while bound layers expose typed KV or conv/SSM views. A synchronous copy after `_model_forward`, before postprocess/sampling, captures a known prompt endpoint before release. | Chosen for this one-request prototype. Small explicit source patch, no scheduler modification or transport dependency. |
| C: offline `LLM` and direct tensor reads | An in-process executor could reach the same runner. After `generate()` the scheduler may already have released/recycled the request's blocks; the public result contains no safe state lease. Multiprocess execution further separates the runner. | Useful as a driver only if paired with B. Reading cache tensors after generation without retained ownership is rejected. |

## Restrictions and unverified behavior

- Exactly 64 blocks, attention layers 3,7,...,63 and 48 GDN layers. Four 256-dimensional KV heads; GDN channels 10240, history 3, state [48,128,128]. Model class and HF geometry are checked in the hook. Target layout comes from the existing GGUF identity reader; its canonical JSON fingerprint is recomputed, including vocabulary hash.
- BF16 or per-tensor FP8 E4M3FN/E5M2 KV only; BF16/f32 conv and recurrent state only. FP8 scale must be finite and positive. FP16, per-token/per-head quantization, FP4, unknown state records, mixed groups, different head shapes and speculative checkpoint slots refuse. Weight FP8 does not imply KV FP8: the launch below first uses BF16 KV.
- One request, TP/PP/DP/CP=1, original GPUModelRunner, synchronous eager execution, no adapters, images, embeddings, speculative decode or MTP. The patch refuses a runner whose original SHA-256 differs from `4cf95efe4ea8caa3110dcd231ff95ceb97e8136f5056e6bdd388300a484c4a81`.
- Block size is read from the actual cache specs, must agree across groups, be a multiple of 16 and be at most 4096. Both endpoints must be whole manager blocks. Cached-token counts alone are not a state lease. Null or recycled block indices refuse. Too large a cached hit cannot be split retrospectively because old GDN endpoints are unavailable.
- The capture's `source_contract` names the inspected tag contract, not a claim about a wheel's build commit. The patch hashes the actual runner file; the hook also checks runtime version and live shapes. CUDA cache binding, kernel page mapping on that host, conv history chronology, state numerical conventions, BF16/FP8 scaling and checkpoint ownership still need the live GPU run.
- The target GGUF hash identifies the receiving file, not the FP8 server weights. Matching layout does not establish matching weights, tokenizer semantics or logits. Operators must bind the same checkpoint/token IDs and record source provenance. Both Q4_K_M and BF16 comparisons are experimental and uncalibrated until measured. No speedup is claimed for the Python conversion.
- Import carries no boundary logits. The existing bench checker consumes one identical probe token after import, then compares full-vocabulary next-token logits with local prefill. It therefore measures N+1 and later, not the already-computed vLLM logits at N. This limit must remain visible in results.

## GPU-host procedure for the orchestrator

Run the script from the reviewed `m3-vllm-bridge` checkout. Reserve exclusive use of the GPU and vLLM environment while its runner is patched. No installation or model download is performed. Every command first runs `gather_test.py` with real torch CPU tensors and CUDA hidden. **STOP if this test fails.** Do not skip it: GPU logits cannot detect a joint K/V page or token permutation.

```sh
EXPECTED_REF=FULL_REVIEWED_R6_SHA bash tools/hybrid-vllm/gpu-run.sh gather
```

Use the full reviewed r6 head SHA for `EXPECTED_REF`, and run the following command with the same value. Each invocation is a child Bash process: failure returns to the operator's shell. Do not source the script or set interactive `errexit`.

```sh
EXPECTED_REF=FULL_REVIEWED_R6_SHA bash tools/hybrid-vllm/gpu-run.sh all /root/proto/runs/hybrid-d-r6-smoke
```

`all` runs `gather`, `build`, `capture`, `convert`, `check`, then `import`, stopping at the first failure. Individual subcommands support inspection between steps; pass the same `RUN_DIR` argument or environment each time. Parents are created with `mkdir -p`, including on a fresh clone without `.temp`. The default is `$PWD/.temp/hybrid-d-r2-261101-gpu`. Capture attempts refuse reuse; use a fresh run directory on retry. Set `BUILD_DIR` to the previous run's absolute build path to reuse it through `all`, `build`, `capture`, `check` or `import`. Partial conversion output is retained for diagnosis; a retry needs a fresh conversion directory and must not mix chains.

The first gate checks contiguous and strided BF16/uint8 cache views, manager/kernel ratios 1, 2 and 3, non-monotonic block tables and append intervals against independently enumerated little-endian bytes. It calls the same `write_attention_pages` used by `export_snapshot`, without vLLM doubles. It does not qualify CUDA views, scheduler ownership or recurrent endpoints.

The build subcommand checks `HEAD == EXPECTED_REF` (full 40-character SHA) and refuses tracked or untracked files reported by `git status --porcelain --untracked-files=all` before and after the build. A second porcelain read includes ignored files under `CMakeLists.txt`, `cmake`, `common`, `ggml`, `include`, `src`, `tools`, `vendor` and `tests`, so a self-ignoring untracked `.gitignore` cannot hide a new source there. Only ignored `.pyc`/`.pyo` files directly under `__pycache__` are exempt; tracked changes still refuse in the first porcelain read, and ignored `.py`, `.cu`, `.gitignore` and other source paths still refuse. A fresh private `PYTHONPYCACHEPREFIX` plus `PYTHONDONTWRITEBYTECODE=1` prevents children from reading existing bytecode caches or publishing new ones. A separate untracked-file read honors repository `.gitignore` files only, so global/info excludes cannot hide new sources. Skip-worktree and assume-unchanged flags refuse even when porcelain is clean. Keep build/run artifacts in ignored directories such as `.temp/` or outside the checkout; both paths are checked before CMake. An existing build directory must contain a matching `build.ref` and valid `binaries.sha256`; verification reuses it without CMake. An incomplete, stale or changed build refuses without rebuilding. A fresh build runs `nice -n 10 cmake -S "$repo" -B "$BUILD_DIR" -DCMAKE_BUILD_TYPE=Release -DBUILD_SHARED_LIBS=OFF -DGGML_BACKEND_DL=OFF -DGGML_CUDA=ON -DCMAKE_CUDA_ARCHITECTURES="$CUDA_ARCH" -DCMAKE_CUDA_COMPILER="$CUDACXX" -DCUDAToolkit_ROOT="$CUDA_HOME" -DLLAMA_BUILD_SERVER=ON -DLLAMA_BUILD_TOOLS=ON -DLLAMA_CURL=OFF`, then `nice -n 10 cmake --build "$BUILD_DIR" --parallel "$BUILD_JOBS" --target llama-server llama-hybrid-bench-check`. Use the script's `build` subcommand to retain its gates and logs.

`BUILD_DIR/build.ref` and `BUILD_DIR/binaries.sha256` bind the complete bin file set and the resolved loader closure to the checked ref. The build-time receipt hashes every regular file below `bin/` in byte-sorted path order, following symlinks, then all file paths resolved by `ldd` for each receiver in receiver/loader order. This derives dependencies from the actual build, including transitive, future project, system and CUDA runtime libraries outside bin. Reuse recomputes the same manifest; changed bytes, paths, file sets and missing or relative dependencies refuse. The explicit known-project gate also requires static llama, ggml, mtmd and server implementation. `LD_PRELOAD` and `LD_LIBRARY_PATH` are unset before children start. Capture, check and import verify receipts before use and copy them into the current `RUN_DIR`, alongside `source.ref`. Receipts covering only bin, legacy shared builds and receipts only in `RUN_DIR` require rebuilding once; do not regenerate receipts over an unverified build. A system/CUDA runtime upgrade requires rebuilding too. No runtime library name allowlist limits the hash binding. The hash-then-run gap still requires exclusive operator custody of the build and runtime files.

Log files contain traced commands, stderr and exit status; failures print the failing command, exit, log path and its last 30 lines to the terminal. Server output stays in `vllm-01.log` or `client-<quant>.log`, with the PID and wait exit in the command log. INT/TERM/HUP/PIPE exit 130/143/129/141. Curl health/requests and CMake use `setsid` to start isolated command groups with interruptible waits; PID-only TERM can enter cleanup without waiting for the request timeout. Cleanup ignores further INT/TERM/HUP/PIPE and restores and byte-compares the runner before stopping its recorded server PID and active command group. Each stop sends TERM, polls until `STOP_TIMEOUT`, then logs and sends SIGKILL to the server PID or the whole owned command group and reaps the leader. PID-only INT/TERM during CMake therefore stops make and compiler descendants too. A server's signal exit cannot replace an existing nonzero script exit; a closed terminal pipe cannot interrupt cleanup's final report. SIGKILL or host failure cannot run traps: restore the saved `gpu_model_runner.py.original` at the logged runner path before restarting vLLM.

## Disk and memory

Q8_0 KV is 34816 B/token. Native GDN tensor payload is 156893184 B. At this exact base the full native body, including constant metadata, is `156894772 + 34840*delta_tokens` B: 24 B/token attention-cell metadata includes MRoPE positions and token ID. The brief's 156894784 fixed figure is 12 B larger; the native reader/re-export test verifies the source-derived size, so the writer does not pad it. Envelope JSON plus a 4-byte length and 48-byte checksum trailer are additional. The 512 MiB body ceiling admits at most 10906 tokens; a 7840-token operational chunk is 430040372 B (410.1 MiB).

With BF16 KV, BF16 conv and FP32 SSM, a raw capture costs `65536*delta_tokens + 153944064` B. With FP8 KV the token term halves. Captures deliberately retain raw data for audit and are shared by the two target legs; each leg retains its own deltas. At 15680/65072/249312 tokens and chunks <=7840, there are 2/9/32 captures; total disk is raw captures plus deltas, plus at most two temporary body-sized files during conversion. Delete audited captures only after recording their hashes. Tensor conversion works one layer at a time; its temporary Python arrays and KV decode buffers depend on chunk size, not whole context depth. Budget about 1 GiB extra CPU RAM for the converter at 7840 and about 1 GiB scratch disk, in addition to retained raw captures/deltas.
