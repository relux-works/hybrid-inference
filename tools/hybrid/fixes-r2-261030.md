## F1-R2 repair

Every authenticated session route acquires its shared permit before parsing scheduling priority or entering `scheduler.enter`. This includes critical and shadow extends, snapshots, list, info, create and delete. Excess requests return 429 and `Retry-After: 1` before waiting, inference or session changes. Limits remain two permits per client and three globally across four workers. The existing `{"error":"binary response limit"}` error body is retained for compatibility, including on session control and shadow requests.

The simpler serialization option is retained: all session routes remain under the model lease. DELETE therefore cannot invalidate a session referenced by an extend. Health and metrics return before admission and never enter the scheduler. Metrics counters are atomic because they now run concurrently with session changes; the two metric values are individual counter reads, not a transactional pair.

A permit is owned by cpp-httplib `Response::user_data`, whose lifetime extends through `write_response` and response destruction on completion/disconnect. Content setters do not clear this field. This covers queued requests, binary streams, JSON acknowledgements, errors and empty DELETE responses. The old binary-provider-only permit acquisition/releaser is removed. Disconnected queued tickets are removed using the request's connection callback, checked at most every 50 ms while waiting. An inactive lease does not release another request's active model lease. A disconnect during inference can still leave the accepted append committed; clients must resynchronize after 409.

The client rotation, critical priority and session FIFO policy are unchanged. No codec, native engine, decoder or proxy code changes are included.
