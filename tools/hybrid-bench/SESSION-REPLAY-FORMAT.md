# Shared native/API session replay format

Protocol authority: PREREG-E2E.md at the verified preregistration commit. Native and API operators receive the same private session-set JSON and its trusted SHA256, plus the public receipt. Never publish owner text/token IDs without authorization. Provider requests/credentials are dev-d's responsibility; this format sends no requests.

Input hybrid-owner-session-export-v2 retains model_sha256, source_log_sha256, population {scope: all-retained-owner-sessions, inventory_complete: true, start_utc, end_utc}, and sessions. Each session has id, base_ids, base_response_end_utc and turns. Each turn retains source_turn, input_ids, output_ids, request_start_utc, response_end_utc. Optional request_messages, input_text, output_text and tool_intervals preserve the provider-neutral message transcript and original tools. Dates must include timezones. Export the complete declared corpus, not selected examples. Retain extraction/tokenizer/model identity and original-log custody receipts.

The response-end to next-request difference is the inter-turn wait. It is not the request-start gap in old usage statistics. If raw tool intervals exist, retain start/end, tool identity and parallelism; do not add overlapping durations into the wait. The exported waits measure the observed next-request opportunity, including tools/idle/user delays. Report them by that name; call them tool-only durations only when interval evidence establishes that interpretation.

prepare_session_set.py freeze validates the whole corpus and publishes exclusions, counts, chronology and wait distributions. A second select command binds that immutable population hash and writes hybrid-e2e-session-set-v1. Its sets.main and sets.favourable each hold count/status, depth range, wait_distribution and ordered sessions. Each workload has session_digest, base_ids, turns, start_depth and final_depth. Turn count is natural, not fixed at forty. The recorded output_ids are the common future context. Native arms teacher-force them one at a time. API arms may generate their own answer for the fixed recorded length budget, but the next API request must use the exported recorded request_messages, never the newly generated answer. Record the inability of a provider to guarantee an exact output count; do not silently treat its maximum-token budget as an achieved length.

Every result carries protocol/prereg commit/document SHA256, session-set SHA256, frozen population digest, session_digest, group (main/favourable/public), link_series (home/fast), comparison (B/A or C/A), arm, ordinal and input/output/journal hashes. Per turn record incoming_tokens, recorded/generated token counts, wait requested/actual, monotonic start/end, TTFT, decode rate, node compute and catch-up seconds, encrypted TLS bytes and decision/reason. API records additionally carry provider/model/endpoint, input/output usage, cached usage/cost, serialization identity and output-length compliance. Private request_messages must be complete at each turn so provider serialization never reconstructs context from model-generated alternatives.

Use native traces with schema hybrid-production-session-v2 and the same session_digest/turn index to join dev-d's results. Node GPU-service clocks and encrypted TLS TCP-payload counts are native cost inputs, with their stated boundaries. API billed cost is a separate measured input. Portion bins and session-cluster analysis are fixed in the preregistration. Unqualified or failed records remain in the flow table, including no-offload sessions.

The signed r49c PREREG-E2E-AMENDMENT.md supplements the unchanged original registration. Carry both commit/document-hash bindings in the session set and every joined result. Owner sets carry freeze_publication (the verified external inventory receipt). Series plans bind the selected comparison, qualification method/path, mandatory public rehearsal and checkpoint_plan; native traces bind series_plan_sha256. These metadata fields do not change the recorded request/output histories used by the API lane. Public/favourable pairs are descriptive; the five-cluster main claim remains unchanged.
