# Qualification limits and open questions

- A node limits/LRU and B chunk transport/launcher are merged locally on `m1-integrated`. CPU integration and rework evidence is in `RESULTS-hybrid-a-r11-261101.md` and `RESULTS-hybrid-a-r12-261101.md`; 256k native state copying, memory amplification and target-GPU checker allocation still need qualification.
- Heterogeneous admission matches native layout and ordered vocabulary, not base-weight provenance. Exact SHA is required by default. Experimental `--hetero-quant` admits only matching layout fingerprints and rewrites the envelope SHA, bypassing the native SHA guard. Layout shapes do not establish numerical equivalence. Quality remains unverified/uncalibrated: the r11 Q4_0-to-Q8_0 requantization gave KL 0.0145 > 0.01 and top-1 62/64; it does not recover source precision.
- CUDA loading, CUDA cache offload, Metal client build, cross-backend native state portability and the 27B file geometry need real target machines. CPU evidence cannot answer these questions.
- Cross-backend section-11 thresholds need calibration on real target pairs. M2 reports client local partition noise and hybrid/noise ratios without assigning numeric acceptance; cross-backend and heterogeneous runs always remain uncalibrated. Homogeneous GPU status requires same-partition greedy K/K, while CPU retains the legacy numerical/status gate. Selected local partitions are observations, not a worst-case bound. See RESULTS-hybrid-a-r13-261101.md for CPU evidence and target-host commands.
- The synthetic ladder is one growing conversation per mode, not the section-11 50-prompt matrix, multi-client contention, realistic networks or a production security audit.
- The default proxy policy uses estimated prefill/link rates. Operator calibration is required before performance/economic conclusions. Report the active policy with any comparative analysis.
- The capacity table uses explicit packing assumptions, not downloaded model sizes. Actual GGUF metadata and available memory take precedence.
- Natural-text driver r27 is CPU-qualified only. GPU BF16/Bonsai/Mirai and 2B/4B/9B runs, effective Mirai trunk admission, MTP-disabled greedy equivalence, long-context capacity and cross-backend portability remain unqualified. The r6q client schedule findings require regeneration of old references; fresh-prefix probes measure selected positions, not a universal schedule floor. On the GPU, budget two simultaneous native scorer contexts for imported arms and extra sequential prefills for probes. First-fetch Gutenberg pins must be retained before publication; the repository source URL list is not itself a frozen corpus.
