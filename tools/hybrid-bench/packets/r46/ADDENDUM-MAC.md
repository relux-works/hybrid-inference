## Import calibration and required rate fixtures

The r44c fit is reusable only with exact import-source and client binary/library identities. Before instrumentation, the relevant native import paths matched r44c; this change modifies those sources and the Mac binary hashes are not present on agents1. The packet therefore refuses the old fit and uses one fresh pass. `import_identity` fingerprints import sources, all stamped executables/libraries, build metadata and model; `mac_timing.py` checks the binding before its link probe. A CPU executable hash is not proof about the old Mac executable.

Run calibration once per model through the same PRI-31 supervisor with the launcher still running. The new helper locally warms the full base, uploads tokens to synchronize the node without downloading a base delta, then imports six append sizes with one generated token each (Glimmer512/1024/2048/4096/6144/2048; paired Qwen sizes below). For Qwen r46c uses two six-point profiles512/1024/2048/512/1024/2048 (one repetition each), sharing the same2GB cap. Smaller deltas retain three sizes and a1536-token span. Expected combined bodies are about1.91GB plus request/framing allowance; a geometry-derived compressed response reservation subtracts only recurrent tensor savings. It uses the existing r44 NNLS fitter. There is no checker or snapshot capture. Old-slot recovery save remains inside import time. The fit has no independent conditioning-depth coefficient; points grow from100k Qwen or76k Glimmer, and retain raw stage/final/save totals.

```bash
python3 tools/hybrid-bench/packets/r46/calibrate_import.py --client-state "$RUN_ROOT/client" --output "$RUN_ROOT/calibration/one-pass" --r44-packet "$R44_PACKET" --with-bf16 > "$RUN_ROOT/calibration-01.log" 2>&1
```

The command above is Qwen. Omit `--with-bf16` for Glimmer; its existing single f32 profile is unchanged. The enforced combined cap is2,000,000,000 bytes for Qwen or3,000,000,000 for Glimmer, shared by foreground/background synchronization, cleanup and native checkpoint requests. A reservation covers exact request bytes, a geometry-derived maximum response and64KiB framing allowance before dispatch; failed/interrupted requests consume their full reservation. A rejected pass retains `calibration.json`, never publishes `import-fit.json`, and must not be retried automatically. `--budget-bytes` can lower the cap. There is exactly one six-point repetition per dtype, without automatic retries. Expect about1.91GB combined Qwen or0.2GB Glimmer body traffic plus reservations/headers. The absolute cap, rather than this estimate, governs dispatch. At0.8 MB/s the caps alone imply up to42/63 minutes of transfer, at2.8 MB/s12/18 minutes; compute/save time is additional.

The code bounds application bodies plus its framing allowance. It cannot bound TCP retransmission or encrypted SSH overhead already queued below HTTP. Record physical interface counters in the supervisor; a strict physical-byte cap needs a transport-level limiter, which this packet does not claim. Keep setup,403 MB link probe and the timing run separate from the import-calibration cap. Budget enforcement also reserves cleanup headroom and never bypasses it for DELETE.

Set `IMPORT_FIT="$RUN_ROOT/calibration/one-pass/import-fit.json"` and, for Qwen, `BF16_IMPORT_FIT="$RUN_ROOT/calibration/one-pass/bf16-import-fit.json"`. Neither fit is published if the paired pass fails. Both bind dtype, model, source and binary/library identity; f32 coefficients never silently stand in for the bf16 runtime fit.
