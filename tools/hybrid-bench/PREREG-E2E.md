# Preregistration: recorded-session end-to-end hybrid measurement

Protocol: hybrid-e2e-prereg-v1, 2026-11-05. This document is committed with a verified machine signature before selecting sessions or running inference. Every selection, series, arm and analysis artifact must quote this immutable commit and document blob hash. Amendments require a new signed preregistration, must preserve earlier results and must precede any affected inference. R49's earlier large-output selection and free-running journals are superseded for this study. Historical results are not pooled with this protocol.

## Question and paper statement

"We replay recorded sessions with identical message and tool-output tokens, recorded response lengths and recorded waiting intervals in every arm. This measures system time and resource use for a fixed workload. It does not measure agent task success or the quality of independently chosen actions."

The main question is whether hybrid inference reduces end-to-end system time on an unfiltered random sample of the owner's long sessions, including their natural small/large portion mix and real waiting opportunities. Large tool outputs are a separately labelled favourable case. A favourable-case gain cannot establish the main result.

## Frozen population and sampling

Obtain one immutable export of all retained owner sessions in the declared date range, with a trusted SHA256, inventory count, exclusions and extraction receipt. Do not apply model-runtime, predicted-route, portion-size, tool-duration, cost or observed-performance filters. Native context limit is 262144; execution capacity is 229376. Only complete, append-only, un-compacted token histories with response and request timestamps qualify. Deduplicate by the full recorded token/timestamp content digest, not source filename. Record malformed, missing, duplicate and nonqualifying sessions and their reasons. Never silently discard a sampled failure or replace it with a faster session.

For each history, choose its first recorded turn boundary with prior context >=100000 and <200000 tokens, then retain every consecutive turn through the first complete response reaching >=200000. No forty-turn cap or lower bound on incoming portion sizes applies to the main series. Refuse a history whose selected final depth plus 2048 exceeds 229376. The evidence lists turn counts, initial/final depths, all portion sizes and all exclusions. This eligibility rule concerns replayability and context capacity, not a route mix or promised gain.

Sample exactly five distinct eligible histories without replacement. Rank by SHA256 of UTF-8 `hybrid-e2e-prereg-v1/main/261105/` followed by the content digest, with digest as tie-breaker; take the first five. The fixed seed is 261105. Publish the frozen inventory hash before any timing and retain every selected history regardless of its speed or number of offloads. Fewer than five is a blocked main series; do not widen the rule post hoc. The corpus freeze is part of selection evidence; the fixed seed must not be used to try multiple inventories.

Separately rank the remaining eligible histories by SHA256 of `hybrid-e2e-prereg-v1/favourable/261105/` plus digest. Take three that have at least twelve incoming portions >=2000 tokens and at least three >=10000. Label every output "favourable case" and never merge it into the main estimate. If fewer than three exist, report the gap without replacement from the main set.

A third, public reproducibility series contains at least one complete session built from a pinned public repository tree, with source URL/commit, exact file list/content hashes, deterministic tool-command transcript, tokenization receipt, recorded responses and tool timestamps. It uses the same replay/arm/analysis format but is labelled constructed public-repository workload, never random owner evidence. Publish the complete artifact; do not claim that a synthetic timing distribution came from owner logs. The repository artifact and session set must be frozen before its inference.

## Identical work and waiting

Use the same base tokens, ordered recorded incoming tokens, recorded output token IDs and output lengths in every native arm. Recorded output tokens are teacher-forced one at a time through the normal decode loop; this is not a batch prefill substitute. For recorded length N, emit exactly N positions using the native first-token sample and N-1 subsequent decode evaluations; the last token is normally evaluated at the next request boundary as in production. Reject token-count, durable-prefix or input-hash differences. No arm may append its own free-running answer to the next turn. Keep free-running divergence as a separate 64-position quality diagnostic only.

Derive each inter-turn wait from the preceding recorded response-end timestamp to this request's start, never from request-start-to-request-start. Validate nonnegative ordered timestamps. Retain raw tool intervals separately where available. Publish count, min/max, mean, median, p90 and p99 for the frozen population and each selected set, plus missing counts. Use sorted nearest-rank percentiles (ceil(p*n), one-based). Verify the cited approximately 8 s/60 s against these actual observations; old aggregate inter-call gaps cannot verify tool time.

Anchor the next request deadline at timed turn completion plus that exact wait. Evidence capture may run only after the turn, within that existing wait; it must not be followed by a fresh full wait. Remaining sleep is max(0, deadline-now). A capture that overruns the deadline contaminates the schedule: preserve the failed attempt and refuse qualification, with no added wait, shortened wait, silent exclusion or automatic reroll. Background catch-up gets no extra evidence/cooldown/checker time. Stop/join it at the final timed boundary before post-session evidence. Checkpoint file hashing, output/trace persistence and checker inference are deferred beyond the timed session where possible. Report raw wall time and any deadline lateness rather than subtracting captures from TTFT.

## Arms, order, hardware and link series

Three native arms: A=local; B=hybrid bf16 with on-demand catch-up; C=hybrid bf16 with background catch-up of committed recorded tokens. f32 remains a separately labelled exploratory control, excluded from the primary comparisons. The policy uses bf16 geometry, measured device PRI31 rates, matching import fits and the measured node link. Empty hybrid arms are valid main outcomes (zero gain/no offloads), not eligibility failures. No samples or policies are changed to force offloading.

Use paired blocks A-B-A-B across distinct sampled sessions for comparison B/A, then A-C-A-C for C/A. Every sampled session appears once in each pair block; the local baseline is measured separately for each comparison. This gives five distinct session clusters, not ten independent baselines or repetitions of one selected case. Alternate the pair-block order between home and fast-link series. Never run all local arms first and all hybrid arms later. Cool down and re-admit the Mac between every arm using the accepted r47 kit's exact supervisor contract; record its ref/hash, raw counters, timing and all refusals. No generic sleep substitutes for missing kit admission evidence.

Run home-link and fast-link series separately on the same frozen sets. Immediately before each series, measure the chosen node with the new eight-stream certificate-verified HTTPS transport; record node identity, interface, UTC/monotonic timestamps, repetitions, actual encrypted byte counts, payload rate and latency. Probe again after each block and record drift; report it, do not discard a slow series. Public-mirror or nearest-city speed tests are context only. The fast-link path is a planned gigabit-class path, not assumed measured. Node GPU, model/quantization, native context, batch/microbatch, dtype, weights/source/binary identities and supervisor conditions must remain declared and fixed within a series. No inference before the required shaped transport qualification and exact kit admission are available.

The API arm belongs to dev-d. Export the same frozen ordered sessions, source hashes, exact message serialization/text, target token IDs and waits. Provider tokenization differs: record provider input/output usage and actual emitted length, and any inability to enforce the recorded output length. An API result that changes the recorded future context or silently substitutes task outputs is out of this paired replay contract. Do not pool API timing with native estimates without those limitations.

## Metrics and analysis fixed before timing

Per turn: incoming portion tokens, recorded output tokens, context depth, system wall and TTFT, decode tok/s, offload decision/reason, on-critical catch-up, concurrent catch-up and join time, node synchronized evaluation/compute wall seconds, envelope bytes, encrypted TLS TCP-payload bytes, payload MB/s, wait requested/elapsed, deadline lateness, and quality/checkpoint status. Preserve local_tail_seconds, meter.local_prompt_ms and reconciliation_seconds. TLS counters exclude TCP/IP headers/retransmissions; retain supervisor physical-interface counters separately. Node wall proxies are not CUDA kernel-active time.

Per arm/session: cold load/base separately; all warm timed turns plus exact recorded waits; raw physical wall; evidence/cooldown/probe/shutdown separately; TTFT/decode totals, total and extra background node GPU-service seconds, and actual bytes. Cost is node measured GPU-service wall seconds times a declared price, plus measured charged traffic times its declared tariff. Also report rented wall-time cost; do not equate service-seconds with a rental bill. No invented prices or free background GPU time.

Portion bins are [0,512), [512,2000), [2000,10000), [10000,infinity). Report count, input/output tokens, summed TTFT, summed timed turn seconds, decode seconds, waits, node seconds and wire bytes for every arm/bin. Use the recorded incoming size for pairing, never route or outcome. Empty bins remain explicit. Show paired gain per bin and the smallest tested bin with a gain; this is a measured interval, not a universal threshold.

Primary endpoint: paired warm session system time including the recorded waits, excluding cold and the separate cooldown/probe/evidence phases. Report all five paired differences and ratios, median paired fractional reduction and a session-cluster bootstrap 95% percentile interval (10000 resamples, seed 261105). B/A and C/A are two separate preregistered comparisons, with their own measured local baselines. Do not treat turns as independent samples. Also report active-only sums, TTFT and cold-inclusive totals as secondary metrics. Preserve failures, no-offload results and all attempted sessions in a flow table; no speed-based optional stopping.

A main-series gain claim requires every selected session's identity/schedule/accounting/quality/admission gates to pass, median paired reduction >=10%, and the corresponding 95% interval lower bound >0. Claim B and C separately, and qualify it by measured link/device. A favourable-only or fast-link-only gain must be labelled as such. No offloads or a failed interval is a non-gain outcome, not grounds for selecting another session. A quality/deadline/resource/protocol failure leaves the affected comparison unqualified, with raw timing retained. Checkpoints use 64 identical teacher positions and >=63/64 top-1; KL and first free-running divergence report, bf16 exact controls remain lossy. No task-success claim is permitted.
